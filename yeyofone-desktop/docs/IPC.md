# IPC schema 1

The main local WebView can invoke only `runtime_status`. Generated application command permissions explicitly allow this command; no shell, filesystem, HTTP or credential plugins are enabled. Remote origins receive no capabilities. Production CSP permits local scripts and IPC; development uses Vite’s development policy.

Request: `{ "schemaVersion": 1, "requestId": "UUID-or-alphanumeric-id" }`.
Response: `{ "schemaVersion": 1, "requestId": "same-id", "sequence": 0, "data": { "engine": "stopped", "callingAvailable": false } }`.
Error: `{ "schemaVersion": 1, "requestId": null, "code": "invalid_request" }`, or `unsupported_version` with a validated correlation ID.

Requests are limited to 512 serialized bytes, deny unknown fields, and require a 1–64 byte ASCII alphanumeric/hyphen ID. Rejected payloads are never echoed or logged. The size check runs after Tauri parses its JSON argument; this is an application validation bound, not a transport-level memory limit. Rate limiting must precede higher-cost commands.

Only an explicit allowlist DTO is serializable; account credentials/native handles do not enter this crate. With the `native-voip` feature, Rust returns its live owner-thread engine state and monotonic sequence; without it, the initial stopped/sequence-zero preview remains. `callingAvailable` remains false. Native initialization/shutdown are internal, and no mutable state command is exposed. The UI asks once on mount, validates correlation/version/shape and discards late replies after unmount. This read-only synchronous command has no side effects to cancel. Mutating asynchronous operations must introduce explicit cancellation before being exposed.

Reserved event envelope: `{ schemaVersion, runtimeId, sequence, data }`. No events are currently emitted. Future producers must serialize all state changes, increment sequence strictly within one runtime ID, emit the resulting snapshot with that sequence, and support snapshot resynchronization. Consumers discard duplicates, resynchronize gaps and reset ordering on a new runtime ID. Preview status uses sequence 0; native state/callback updates increment the runtime sequence. An unavailable native worker returns `engine_unavailable` with the validated request ID.

Official references: [Rust commands](https://v2.tauri.app/develop/calling-rust/), [capabilities](https://v2.tauri.app/security/capabilities/), [configuration](https://v2.tauri.app/reference/config/).

## Account storage command (schema 1)

`accounts_command` accepts `{schemaVersion, requestId, action, account?, id?, password?, turnPassword?}`. Actions: `list`, `save`, `delete`; unknown fields/actions rejected. Save requires the complete public account DTO and, for a new account, a password. Edit with no password keeps the existing vault reference. The complete public DTO contains id, label, username, host, port, transport (udp/tcp/tls), enabled, stunServer, ice, turnServer and turnUsername. Nullable NAT fields use null. Delete requires a bounded account id. Payload limit 16 KB, account limit 32. Responses use the existing correlated schema envelope, sequence 0 (account events/revisions are not implemented), and only public accounts. Never return vault references or passwords. Errors are stable redacted codes, and currently account operation errors are strings rather than the runtime IpcError envelope. Only the main local window is granted this command.

## Registration (schema 1)

`registration_command`: `{schemaVersion, requestId, action, id?}` with strict unknown-field rejection and a 512-byte bound. Actions `status` (no id), `register`, `refresh`, `unregister` (existing enabled account id required). Passwords and native settings are not accepted. Response: correlated envelope, sequence 0 snapshot, array of `{accountId,state,failure,sipCode,nativeCode,expiresInSeconds,attempt,retryInSeconds}`. Polling replaces event streaming in this phase; correlation/generation checks discard stale UI responses. Failure values: sip_authentication, sip_rejected, dns, tls, transport, offline, timeout, vault_unavailable, engine_unavailable, capacity. Commands run native work on the owner actor and native vault reads on a background worker. No-provider-ack state is never labeled Registered. Preview builds return engine_unavailable. Only the local main window has command access.

## Phase 7: validate_destination
Request: `{schemaVersion:1, requestId, destination}`. Strict fields, 2048-byte wire limit, destination max 512 bytes. Returns versioned correlated sequence-zero response with `{kind, normalized, callingAvailable:false}`. Invalid destination returns sanitized `invalid_request`. This command performs pure validation only, accesses no accounts or credentials, and cannot initiate calls. See PHASE-07-REPORT.md for the supported subset.

## Phase 8–9: calls_command
Strict request `{schemaVersion:1, requestId, action, id?, accountId?, destination?, muted?}`. Actions: status (no extra fields), dial (id/accountId/destination), hangup (id), mute (id/muted), answer (id), reject (id). Wire max 2048 bytes; identifiers max 64 safe ASCII characters; destination validated through domain parser. Response is versioned/correlated, sequence-zero snapshot of at most 128 public sessions `{id, accountId, destination, direction, caller, state, reason, sipCode, durationSeconds, muted, audioActive, audioError}`. No native handles, passwords or raw SIP reason strings. Dial checks enabled persisted account and live registration again on the serialized owner thread. Incoming caller IDs are limited to a sanitized SIP user string. An incoming call rings for 30 seconds before SIP 480; user decline sends SIP 603. The local app polls while its process is open, presents the incoming-call window and brings the main window forward. There is no system notification when the app is closed, because its SIP engine and registration stop with the process. See PHASE-09-REPORT.md.
